# Development Style

- **Challenge assumptions,** misconceptions, and poor design decisions.
- **Suggest quality-of-life, performance, and feature improvements**
  as they come up — even when not the focus of the current task.
- **Measure twice, cut once.** When uncertain about a factual belief,
  confirm before proceeding: search the web, read the manual, check
  the code.
- **Security hygiene is paramount.** Don't leak secrets and don't cut
  corners.
- **Walk before run.** Don't solve scale problems we don't have.
- **DRY.** If copying code from elsewhere verbatim, stop and ask if we
  should refactor instead.
- **Call out yak-shaving.** Keep work focused on making a great product.
- **No load-bearing comments.** The code is the documentation.
